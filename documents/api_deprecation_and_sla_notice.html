Platform API Deprecation & Service Level Notice

Notice ID: ENG-SLA-2026-09 | Effective Date: 2026-04-01 | Audience: Enterprise API Consumers

Section 1: Version Lifecycle & Deprecation Windows

1.1 Major REST API versions remain generally available for at least twenty-four (24) months following successor release. Deprecation notices are published in release headers via the Sunset HTTP header and emailed to registered organization administrators at least one hundred eighty (180) days prior to end-of-life.

1.2 Endpoints marked as experimental (/v1alpha/*) carry no backwards-compatibility guarantee and may be retired with thirty (30) days notice, except where a Customer executes a written Early Access Addendum referencing Clause 3.1.

1.3 Legacy v1 Sunset Schedule

  • 2026-06-30: v1 write endpoints transition to read-only mode (HTTP 410 Gone for POST/PUT/DELETE).
  • 2026-09-30: Complete decommission of v1 authentication tokens & webhook signing keys.
  • 2026-10-15: Enterprise migration hold grace period expires — automated traffic cutover occurs unless an extension waiver is active.

Section 2: Service Level Objectives & Latency Targets

2.1 For Enterprise tier tenants, Acme Cloud guarantees monthly API uptime ≥ 99.95% with p95 synchronous query latency < 250 ms and p99 ingestion batch acknowledgement < 1200 ms under standard burst quotas.

2.2 Rate Limiting & Fairness: Standard API keys allow up to 600 requests/minute per workspace. Burst requests with payload_bytes <= 1048576 and concurrent_streams < 25 receive priority queuing; oversized payloads > 10 MB are rejected synchronously with HTTP 413 unless streamed via the multipart upload API.

Section 3: Migration Waivers, Exceptions & Service Credits

3.1 Written Migration Extension: An Enterprise Customer experiencing documented third-party ERP integration dependencies may request a single ninety (90) day extension beyond the Section 1.3 sunset date, provided that (a) a remediation timeline with engineering milestones is submitted forty-five (45) days before cutoff, (b) legacy traffic originates exclusively from allowlisted static egress IPs, and (c) the customer acknowledges that v1 TLS cipher deprecation cannot be deferred beyond regulatory compliance deadlines. Extension requests require joint approval from the Platform Product Lead and Security Engineering.

3.2 Exclusions from SLA Calculation: Availability calculations exclude Scheduled Maintenance Windows announced seventy-two (72) hours in advance, force majeure events, client-side misconfigurations (including expired OAuth credentials or TLS 1.1 clients), and traffic exceeding contracted rate-limit bursts under Clause 2.2. SLA credit claims must be submitted within fifteen (15) business days after the end of the affected billing month, referencing Service Level Objective definitions in Section 1.2 of master_services_agreement.pdf.
